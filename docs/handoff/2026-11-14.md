# Plan 2026-11-14: precision first, then the runtime, then coding agents

Written on the owner's Mac. It closes the open questions from `2026-11-03.md` and fixes the order of the next work.

## What the evidence says

- **0.2.0 is live** (site download and GitHub). The live update feed is still empty. The signed 0.2.0 `appcast.xml` is
  now committed in PR #30, but the site build takes the feed from the live site, so only a deploy from the Mac fixes it.
- **main has 10 unreleased commits**: the EN/DE/ES/FR language packs, positioning and the site build. They were written
  from a Linux session and checked by CI only. On the Mac (2026-11-14): `swift test` passes 452 tests, and
  `yaz eval --quiet` scores 0.
- **Real use, 2–11 Nov (local history, not committed):** 57 dictations. 46 went to Ghostty, Cursor or Claude: yaz is
  used to talk to coding agents.
- **Term repair is wrong in real use.** It made 5 replacements and 4 of them were wrong. Three come from the default
  vocabulary and happen on main with `yaz vocab test`, all at score 0.749 on the skeleton path:
  - `inputuna` → `Notion`
  - `mergele` → `merge` (the Turkish verb suffix is lost; `mergele` was already right)
  - `koda sor` → `Cursor` (so "Claude Code'a sor" is broken)

  The other two came from screen-context terms: `Kreatini` → `Kreatin` (suffix lost) and `Fitbit Air'ın` →
  `Fitbit'ın` (a word lost). Eval scores 0 while this happens: **the metric cannot see real Turkish.**
- **Learning has never fired.** In 9 days: 4 observations, 1 rightly rejected (`düzenli` → `düzenle`), 0 rules learned.
  Most dictations went to terminals, where the field read-back probably sees nothing. This is not verified yet.
- **A runtime audit** (read-only, 2026-11-14) confirmed 18 findings in the source. The dictation loop itself (`Daemon`,
  `HotkeyMonitor`, `AudioCapture`, `TextInjector`, `FieldReader`) has almost no tests. The 452 tests cover the language
  packs, vocabulary and post-processing.

## Decision

1. **0.2.1**: term repair stops changing ordinary Turkish. It ships from the Mac, and the same deploy fixes the feed.
2. **0.3.0**: the runtime loses no text silently, and the language packs ship only after a check with audio.
3. **After 0.3.0**: build on coding-agent dictation, the use the data shows.

**Not now:** a Rust/cross-platform rewrite, a new name for abroad, new language packs. Revisit them after 0.3.0, with
usage data and with users outside Turkey.

**Urgency:** the owner stopped using yaz on 11 Nov because of the wrong replacements. 0.2.1 is the next thing to do.

## 0.2.1: term-repair precision

Branch `release/0.2.x` from `v0.2.0`. The fix goes to main with `git merge`, never a rebase.

1. **Eval cases first, in their own commit.** Cases must be made up: the repository is public, so the history sentences
   are not committed. Each case uses the same kind of word in new sentences:
   - loanwords with a Turkish verb suffix: `mergele`, `pushla`, `deployla`, `commitle`
   - inflected loan nouns: `inputuna`, `outputu`, `branchi`
   - spans that include a Turkish word: `koda sor`, `slacke yaz`
   - "Claude Code'a sor" as a must-fix

   The owner approves this commit. At the end of this step, the score on the current code must be above 0. If it is
   not, the cases miss the bug.
2. **The fix, with the `research/program.md` loop**:
   - a term followed by a Turkish suffix keeps the suffix
   - a span that contains a common Turkish word is never replaced
   - the skeleton path needs more than 0.749, or a guard on length or first letter

   Keep a change only when the score goes down and the tests pass.
3. **Screen-context terms** keep the suffix (`Kreatin'i`, or the word left as it is) and never drop a word.
4. **`yaz eval --history`**: a local-only command that runs the current pipeline over the replacements in local history
   and lists them. Use it on this Mac to check before each release. It never writes anything into the repository.

**Done when:**
- The new cases score above 0 before the fix and 0 after it.
- `swift test` is green.
- `yaz eval --history` shows none of the 4 wrong replacements, and `Cloud` → `Claude` still happens.
- 0.2.1 is released with `release.sh --deploy`, and the live feed lists 0.2.1.

## 0.3.0: the runtime and the language packs

**Scheduled hardening** (numbers from the audit; every fix comes with a test, so the `Daemon` loop gets a testable seam):

| # | Problem | Fix |
|---|---|---|
| 1 | A paste that never happens erases the dictation (Accessibility revoked or secure input is on, then the clipboard restore). | Check the permission and secure input before the paste. On failure, skip the restore and show a note. |
| 2 | A failed transcription loses the audio silently. The timeout is a fixed 120 s, but a recording can run 10 minutes. | Scale the timeout with the audio length, keep the last failed recording for a retry, show the error. |
| 3 | A key press while the last dictation is still processing is ignored. | Queue it, or at least show "busy". |
| 4 | A stuck recording (missed key-up) gets transcribed and pasted. | Stop at the cap, and check the real key state while recording. |
| 10 | The field read-back can block the main thread. | Set the AX timeout explicitly and read off the main thread. |
| 11 | A typo in `config.json` lets Settings save the defaults over the whole file. | Never save over a file that failed to parse; back it up. |
| 12, 13 | `learned.json` and `personal.json` reset on a decode error; `--forget` does not stick. | Back up and add a schema version; reload or merge before saving; run learning one at a time. |

**The terminal question:** check whether the read-back works in Ghostty. If it does not, the menu says so, and learning
in terminals goes to "after 0.3.0".

**The language-pack gate:**
- Make `say -v` fixtures for en/de/es/fr, with the same discipline as the Turkish ones.
- Run them through `yaz transcribe` and the pipeline, and write the results in `docs/architecture.md`.
- Launch the app from main, switch the main language in Settings, and dictate once in each language.

**Tracked, not scheduled:** audit #5–9 and #14–18 (the timeout with work that ignores cancellation, preview cost on long
recordings, no retry after a failed model load, mic permission and device changes, permission revocation after launch,
a common word learned as an alias, MCP cancellation, the hard-coded ⌘V key code on Turkish-F, smaller items). Promote
one when real use hits it. #15 (MCP cancellation) goes first in the coding-agent work.

**Done when:** every scheduled item has a test, the language packs passed the gate, 0.3.0 is released from the Mac, and
the feed lists it.

## After 0.3.0: dictation for coding agents

The direction comes from the data: most dictations go to a terminal or an agent. In this order:

1. Default app profiles for terminals and agent apps (Ghostty, Cursor, Claude): code mode and the chat style, without
   any setup.
2. `yaz mcp`: fix cancellation (audit #15), then extend what `wait_for_dictation` does.
3. Learning in terminals, if the 0.3.0 check showed it is blind there.

Use 0.3.0 for 2–3 weeks before you add more. The usage data decides the next step.
